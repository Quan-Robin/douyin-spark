# v0.5.3 — 修复「用换行分隔多个好友,只发第一个」

## 🐞 症状

在好友名里用**回车换行**写多个名字(如 A↵B↵C),保存后**只有第一个**被发送;
「消息池」多行也可能同样失效。表现为"换行识别失效"。

## 根因(最可能)

好友名/消息池用的是普通输入框 `Ui.input()`,它**没有声明多行文本**
(`TYPE_TEXT_FLAG_MULTI_LINE`),也没关掉输入法的**回车动作键**。
不少输入法(尤其系统更新后)会把回车渲染成「完成/发送」动作键 —— 按下去**不会插入换行**,
于是文本里根本没有 `\n`,一整段被解析成**一个名字**,自然只发第一个人。

> 这是"输入侧"的问题:解析器本身是按换行切分的(见下方验证),代码没问题,是换行从来没进到文本里。

## 修复

1. **新增 `Ui.inputMulti()`**:显式设置
   `TYPE_CLASS_TEXT | TYPE_TEXT_FLAG_MULTI_LINE`、`setSingleLine(false)`、
   `IME_FLAG_NO_ENTER_ACTION`(强制回车插入换行)、多行 + 顶部对齐;
2. **好友名 / 消息池共 4 处**改用 `inputMulti()`(无障碍页 + 协议页);
3. **解析侧加容错**:`parseFriends()` 与 `messages()` 改为按**任意换行符**切分
   (`CRLF`、单独 `CR`、Unicode 行分隔符 `U+2028/U+2029`),复制粘贴来的名单不再受行尾字符影响;
4. **保存后回显数量**:保存好友后弹出「**已保存 N 个好友**」——
   如果换行没生效,当场的数字就会是 1,不用等到第二天才发现只发了一个人。

## 验证

| 检查 | 结果 |
|---|---|
| 资源 / Java 编译 | 通过 |
| R8 + 签名 | 通过(dex 205.5 KB) |
| 源码确认 | 4 处 `inputMulti()` 调用、`IME_FLAG_NO_ENTER_ACTION` 已设置 |
| 解析逻辑 | 按 `[\r\n\u2028\u2029]+` 切分,容错多种换行 |

> ⚠️ **未能自动验证的部分**:不同输入法对回车键的处理只能在真机上确认。
> 请按下面的步骤实测 —— **Toast 里的数量**就是判定依据。

## 请这样验证

1. 打开「无障碍模式」页,好友名里输入三行(每行一个好友);
2. 点保存,看 Toast:**显示「已保存 3 个好友」= 修好了**;显示「1 个」= 换行仍然没进文本,请把输入法名称告诉我;
3. 顺手确认消息池的多行也是每行一条。
