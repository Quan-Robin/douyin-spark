# douyin-spark-mobile 🔥 抖音自动续火花(手机版)

在 **Android 手机**上自动续火花的方案:通过无障碍服务操作手机上**已登录**的抖音 App,每天定时自动给指定好友发一条消息,维持火花不断。

- ✅ **不依赖电脑**:定时、发送全部在手机本地完成
- ✅ **常驻登录**:登录态由抖音 App 自身保持,脚本无需处理任何登录(没有网页版方案在手机上掉登录的问题)
- ✅ 每日防重发、消息池随机、失败重试、全程日志
- ✅ **独立 APK**(原生实现,无需安装 AutoX.js):`SparkKeeper.apk`
- ⚠️ 仅支持 **Android**(iOS 系统不允许第三方 App 自动操作其他 App,无解决方案)
- ⚠️ 发送消息本身需要网络;"离线"指不依赖电脑常开,不是断网发消息
- 📌 当前版本 **v0.3.4**:修复抖动设置互相覆盖、Root 检测无提示;更新说明在弹窗里按手机排版渲染,详见文末「v0.3.4」

## 方式一:安装独立 APK(推荐,已构建好)

APK 位于本项目根目录:**`SparkKeeper.apk`**(约 68KB,原生实现)。共申请 7 项权限:开机自启、前台服务、唤醒锁、精确闹钟、**网络**(协议模式的内嵌网页必需)、**悬浮窗**(后台拉起抖音 / 离屏网页必需)、**修改系统设置**(可选的「静默亮度」必需)。不申请存储、定位、通讯录等权限,也没有任何统计或上报 SDK。

1. **安装**:把 `SparkKeeper.apk` 传到手机(微信文件传输/数据线/网盘均可)安装;系统提示"未知来源应用"时允许即可
2. **配置**:打开「续火花」App:
   - 点 **① 开启无障碍服务**(跳转系统设置,找到「续火花辅助」开启)
   - 填 **② 好友名**(填消息列表里显示的名字:设了备注就填备注名,没设就填昵称)
   - 填 **③ 消息池**(每行一条)
   - 设 **④ 每天发送时间** 与随机抖动
   - 勾选 **⑤ 选项** —— **首次测试保持勾选"测试模式"**
   - 点保存后若提示授权 **「显示在其他应用上层」(悬浮窗)**,请允许——这是后台自动拉起抖音的必需豁免
   - 首页状态区会实时显示无障碍/悬浮窗/下次运行/今日发送状态
3. **测试**:点 **立即运行一次** → 观察抖音被自动打开、进入聊天、输入消息但**不真发**即流程通畅
4. **正式**:取消勾选"测试模式" → 点 **⑥ 保存并设置每天定时** → 完成

> **开启无障碍时若弹出"系统已拒绝向此应用授予访问权限"**(Android 13+ 对**所有侧载安装应用**的保护,与 App 版本无关,两种解锁方法任选):
> - **方法 A(手机上操作)**:设置 → 应用 → 全部应用 → 「续火花」→ 右上角 ⋮(或圆点)→ **允许设置受限权限**(部分系统会先要求把电池优化设为"不受限制"),完成后回到 无障碍列表 找到「续火花辅助」开启
> - **方法 B(电脑 adb,开发者推荐)**:手机开启 USB 调试连电脑后执行
>   `adb shell appops set com.spark.keeper ACCESS_RESTRICTED_SETTINGS allow`
>   然后直接到无障碍列表开启即可

**锁屏行为**(与脚本版一致):滑动锁/无锁自动亮屏解锁、跑完自动回锁;密码/指纹锁不能被越过,App 会等你下次解锁后自动补跑。

**排查**:日志在 `Android/data/com.spark.keeper/files/logs/`,界面结构 dump 在同目录 `debug/`(任何一步卡住都会自动保存当时屏幕的控件结构)。把文件发出来即可适配。注意部分手机文件管理器看不到 `Android/data`,可用手机自带"文件管理"搜索或连电脑查看。

**保活三件套(定时可靠、无障碍不被杀的前提)**:
- 系统设置 → 电池 → 「续火花」和抖音 → **不限制后台/关闭电池优化**
- 厂商自启动管理中允许「续火花」**自启动**(开机后闹钟自动恢复)
- App 内默认开启**常驻保活**(通知栏有一条"续火花守护中"低调通知,保持进程前台优先级,避免无障碍随进程被杀);划掉最近任务会把进程和无障碍一起杀掉,建议在最近任务里**锁定**「续火花」卡片

**小米/澎湃(_MIUI/HyperOS_)用户必读**:
1. 系统设置 → 应用设置 → 应用管理 → 「续火花」→ 开启**自启动**,省电策略设为**无限制**
2. 同一路径下如有**「后台弹出界面」**开关,一并允许
3. 授予 App 内提示的**「显示在其他应用上层」(悬浮窗)权限**——它同时是安卓原生(targetSdk 30+)与小米拦截层的双重豁免通道,是后台拉起抖音最关键的一项
4. 「续火花」被拦截时日志会出现 `12 秒内抖音未到前台` 并给出上述检查清单;`debug/dump-launch-blocked-*.txt` 是现场记录,可发出来进一步定位
5. 抖音本身也建议加白名单(省电策略无限制),避免它在后台被冻结

**中途停止**:App 首页有**停止运行**按钮,点击后流程会在当前步骤结束后退出(包括等待解锁的长等待也会被立即打断)。

**好友名填什么**:填**消息列表里显示的名字**——你给对方设置了备注名就填备注名,没设置就填昵称(以此为准,不要用抖音号或搜索用的名字)。多个好友用逗号(全半角均可)、顿号或换行分隔。

**给不同好友指定不同消息(实验性)**:在好友名后用 `=` 接专属消息池,多条消息用 `|` 分隔;不配置的好友使用全局消息池:

```
小明,小红=专属消息A|专属消息B
老王=今日也要开心呀 {{friend}}
```

(要给多个好友分别配置专属消息时,建议一人一行写。)

**界面结构(v0.2.2)**:主界面 = 左侧图标侧边栏(🏠 首页 / 📱 无障碍 / 🌐 协议 / ⚙️ 设置 / ℹ️ 关于)+ 右侧内容区;顶部标题栏含返回箭头与三点菜单(设置 / 检查更新 / 关于)。好友/消息/时间配置在「设置」页,两种模式数据互通;各模式页只保留基本功能(登录、运行控制),高级选项全部收进「设置」。

**实验性:协议模式(内嵌网页后台直发)**:真正的完全后台方案——App 内嵌 WebView 打开抖音网页版,登录一次 Cookie 长期保存;到点在离屏 WebView 里自动「找会话 → 输入 → 发送」,不亮屏、不需要无障碍、不依赖电脑。步骤:进入「🌐 协议模式」页 → 点「网页登录」登录一次 → 保存。说明:纯 HTTP 协议直发实测被 `bd_ticket_guard` 设备签名 + `identity_security_token`(由网页安全 SDK 动态生成,无法伪造)挡住,离屏 WebView 让安全 SDK 原生运行、与真人网页操作无差异,是该形态的正确实现;网页改版可能需适配(日志有每步结果)。两种模式并存,勾选协议模式即不走无障碍。

> **v0.2.2 对协议模式的修复**(此前它实际上跑不起来):① 运行标志 `PROTO_RUNNING` 用完不复位,导致**一个进程内只可能成功运行一次**,之后每次都直接返回「协议模式已在运行中」;② 「停止运行」置位的 `ABORT` 在协议链路上没人复位,点过一次停止之后就永远「已手动停止」。此外把页面交互整体重写:所有选择器改成多候选降级链(原来搜索框/编辑器/结果项各只有一条硬编码选择器,改版即失效);「等页面就绪」改成 Java 侧轮询短探针(原来在页面里挂 25 秒定时器,SPA 一跳转定时器就随旧文档消失,必然超时);输入消息改成 execCommand → 粘贴事件 → beforeinput 三级策略并回读校验;回车无效时自动改点发送按钮;离屏 WebView 补上了第三方 Cookie 开关(与登录页保持一致)。选择器链是按在用的开源实现校准的(unmev/douyin-auto-fire、2061360308/DouYinSparkFlow、bling-yshs/douyin-auto-spark、Yuriz132/douyin-cloud-streak)。其中最容易踩的坑是:**页面上有两个搜索框**,顶部那个全局搜索框一旦被填入就会跳离 /chat,所以现在只认左侧会话列表里那一个(横向位置在页面左侧 40% 以内);另外部分灰度把私信 UI 放进 wujie 的 shadow root,`document.querySelector` 会一个都找不到,现已改为跨 shadow root 查询。搜索不可用时还会退回到「在左侧会话列表里按标题点开」;发送结果按「重试/发送失败标记 → 聊天记录里出现自己刚发的消息 → 编辑器已清空」判定;`/chat` 30 秒仍未就绪会自动改试 `/messages`。仍然失败时,日志里会按步骤给出 `搜索框填充失败` / `聊天编辑器未出现` / `页面状态` 等明确结果,配合 `dump-*.txt` 即可继续按新的选择器链适配。

**实验性:Root 解锁密码锁屏**:勾选并填入锁屏 PIN 后,遇到密码锁屏时会通过 Root 直接输入 PIN 解锁(仅支持 PIN/数字密码;指纹/人脸是硬件绑定,任何方案都无法模拟)。PIN 只做了简单混淆(XOR+Base64)后存在 App 私有目录,**不是加密**,root 环境请自行评估风险。

**实验性:静默亮度**:运行时把系统亮度调到最低、结束后恢复(需授予「修改系统设置」权限)。屏幕仍会点亮,但几乎不可见,把"前台运行"的存在感降到最低。注意:UI 自动化必须让抖音在前台才能操作,真正的"完全后台"只有逆向抖音协议直发一条路,风险不可接受,不会做。

**找人的匹配策略**(v0.1.2 优化):先在可见会话区**精确匹配**名字 → 再包含匹配 → 滚动逐轮查 → 搜索兜底;匹配区域排除了屏幕顶部 15%(搜索框/「新朋友」推荐横幅),避免误点同名的推荐用户或聊天预览里出现的名字;点进个人主页时会**先核对顶部昵称**与目标一致才继续,不一致立即放弃——宁可失败也不会发错人。若你的好友名与别人的显示名互为包含关系(如"小明"与"小明同学"),建议在抖音里给对方设置唯一的备注名。

**从源码重新构建**(改了 Java 代码后):Git Bash 中执行 `bash apk/build.sh`,产物覆盖到根目录 `SparkKeeper.apk`(需要 `D:/AI/ZCode/build-env` 下的 JDK 17 与 Android build-tools,构建脚本会自动定位)。

## 方式二:AutoX.js 脚本版

以下章节为 AutoX.js 脚本方案(适合想直接改脚本即时生效的场景),功能与 APK 版相同,二选一即可。

## 原理

```
AutoX 定时任务(每天 HH:MM)
        ↓
启动抖音 App(已登录,登录态常驻)
        ↓
进入消息页 → 按名字定位好友会话(列表直找 → 滚动 → 搜索 三级兜底)
        ↓
聊天输入框写入随机消息 → 点「发送」→ 校验输入框清空/气泡出现
        ↓
写入当日记录(spark_state.json,防止一天内重复发送)
```

自动化载体是 [AutoX.js](https://github.com/kkevsekk1a/AutoX)(开源免费的无障碍自动化框架,Auto.js 的社区维护版):脚本用 JavaScript 编写,改配置即时生效,支持打包成独立 APK。

## 安装

1. 手机下载安装 **AutoX.js**:
   到 [AutoX Releases](https://github.com/kkevsekk1a/AutoX/releases) 下载最新的 `autox.js-vX.X.X.apk` 安装(选择普通版,不是打包插件版)。
2. 给 AutoX.js 授予以下权限(关键,缺一不可):
   - **无障碍服务**:系统设置 → 无障碍 → AutoX.js → 开启
   - **电池白名单**:系统设置 → 电池 → 允许 AutoX.js 和抖音后台运行 / 关闭电池优化(否则定时任务会被杀,这是定时失灵的最常见原因)
   - 厂商系统(小米/华为/OPPO/vivo 等)还需在"自启动管理"里允许 AutoX.js 自启动和关联启动
3. 把本项目 `spark.js` 放进手机,并在 AutoX.js 里导入:
   - 方式 A:把文件放到手机的 `脚本/` 目录(AutoX 默认脚本目录,通常是 `/sdcard/脚本/`),AutoX 主界面即可看到
   - 方式 B:在 AutoX 里新建文件,把 spark.js 内容粘贴进去

## 配置

用 AutoX 内置编辑器打开 `spark.js`,只改**配置区**:

```javascript
var FRIENDS = [
    { name: "好友昵称A", messages: null },   // name 必须与抖音里显示的名字完全一致
    { name: "好友昵称B", messages: ["专属消息 {{friend}} 🔥"] },  // 可单独配消息池
];

var GLOBAL_MESSAGES = [
    "续火花啦 🔥",
    "今日份火花已续上 🔥",
    "打卡续火,不能断 🔥 {{friend}}",
];

var TEST_ONLY = false;   // 见下方"首次调试"
```

## 首次调试(重要)

因为我没有你的真机,抖音控件(按钮位置、控件类型)需要一次真机校准,流程已内置调试闭环:

1. 把 `TEST_ONLY` 改为 `true`,手动运行 `spark.js`
2. 屏幕会出现悬浮控制台,观察流程走到哪一步:
   - 顺利走到 `【TEST_ONLY】已走到发送一步` → 全流程通畅,改回 `false` 正式使用
   - 卡在某步 → 脚本会自动把当时屏幕的**控件结构** dump 到
     `/sdcard/Download/spark_debug/dump-*.txt`,同时日志在
     `脚本/logs/spark-日期.log`,把这两个文件发给助手即可针对性适配
3. 也可以用 AutoX 的**布局分析**(主界面右上角菜单 → 布局分析,切到抖音消息页/聊天页截图查看控件属性),把看到的 `text/desc` 与脚本里的选择器对照修改

调试通过后,把 `TEST_ONLY` 改回 `false`、`DEBUG` 可改为 `false`(不再弹悬浮窗)。

## 每天定时运行

用 AutoX 自带的**定时任务**(不依赖电脑):

1. AutoX 主界面 → 长按 `spark.js` → **定时任务**(部分版本在文件右侧菜单里)
2. 添加每天一次的任务,时间如 `21:30`
3. 建议同时开启:AutoX 设置 → **开机自启动**(手机重启后定时任务仍有效)

运行结果查看:`脚本/logs/spark-日期.log`,当天所有好友都成功后再次触发会直接跳过(防重发);有失败会在下次触发时自动补发失败的好友。

## 打包成独立 APK(可选)

想让它在桌面上像个正常 App:

1. 在 AutoX Releases 下载并安装**打包插件**(packer/打包插件 apk)
2. AutoX 主界面 → 长按 `spark.js` → **打包** → 填应用名(如"续火花")、选图标 → 生成 APK
3. 安装生成的 APK,打开一次并授予无障碍权限即可

打包后的 App 运行逻辑与脚本完全相同,定时任务同样在 AutoX 里设置(或用打包配置里的定时选项)。

## 锁屏运行

脚本默认开启锁屏处理(`HANDLE_LOCKSCREEN = true`),到点时无需亮屏人工操作:

- **无锁屏/滑动解锁**:自动亮屏 → 上滑解锁 → 执行续火 → 完成后自动回锁。全程无人值守。
- **密码/指纹/人脸锁**:Android 安全设计不允许任何 app(包括无障碍)越过生物识别,脚本**不会**也无法替你解锁。此时脚本转入等待:轮询锁屏状态,你**下次解锁手机后自动继续执行**(默认最长等 8 小时,`WAIT_UNLOCK_TIMEOUT_MIN` 可调)。续火花只要当天完成即有效,不必掐准定时那一刻。
- 夜间执行期间屏幕会亮 1~2 分钟属正常现象;完成后(或超时未解锁)系统会按你的锁屏设置自动回锁。
- 夜间深度休眠(Doze)下定时触发依赖**电池优化白名单**,请务必按"安装"一节设置。

相关配置项:`HANDLE_LOCKSCREEN`(总开关)、`WAIT_UNLOCK_TIMEOUT_MIN`(等待解锁时长)、`LOCK_AFTER_DONE`(完成后回锁)、`UNLOCK_SWIPE`(解锁手势自定义,默认上滑)。

## 常见问题

**定时任务到点没运行**
九成是电池优化杀了 AutoX:把 AutoX 和抖音都加入电池白名单 + 自启动;部分厂商需要在最近任务里"锁定" AutoX。

**卡在"未找到底部消息入口" / "打不开会话"**
抖音版本控件差异。运行时把 `DEBUG` 开着,拿 `/sdcard/Download/spark_debug/` 下的 dump 文件来适配;或用布局分析自行核对"消息"两个字的 `text`/`desc` 属性。

**"无法写入输入框"**
抖音聊天输入框在个别版本不是标准 EditText。dump 一下聊天页,若输入框是其他类名,把 `sendMessageInChat` 里的 `className("android.widget.EditText")` 换成 dump 里看到的类名即可。

**消息发出去了但算失败**
看日志最后一步:校验依赖"输入框清空"或"气泡出现",若抖音界面结构特殊导致误判,把 `send-verify-fail` 的 dump 发来适配。

**双开/分身的抖音**
脚本启动的是主应用(包名 `com.ss.android.ugc.aweme`),分身包名不同无法直接支持。

**风控提示**
脚本带随机延时、消息池随机,但请勿配置大量好友或一天多次;仅适合个人日常使用,请遵守抖音用户协议。

## v0.3.4

**🐞 随机抖动「改不动」——其实是三个输入框互相覆盖**

- **现象**:在「基本设置」里把抖动从 10 改成 20,保存后过一阵又变回 10,像是改不动。
- **根因**:无障碍页/协议页各自也有一个抖动输入框,它们只在**首次进入时**回填一次

  模式页手里还是旧值,再点一次「保存」就把旧值写回去了 —— 保存链路有三条,谁后点谁说了算。
- **修复**:抖动**只保留在「基本设置」**一处,两个模式页改成只读提示(「随机抖动:±20 分钟 · 在「基本设置」里修改」);

**🐞 Root 检测「点了没提示」**

- **根因**:检测代码没有超时、也不排空 stderr —— Magisk 弹出授权框时 `su` 会一直挂着,
  `waitFor()` 永久阻塞,那个后台线程就再也没回来,用户什么都看不到。
- **修复**:先立刻显示「正在检测…(若弹出授权框请点允许)」;执行带 15 秒超时(超时 `destroy` 进程);
  结果分四种情况明确说明:找不到 su / 无法执行 / 超时未响应 / 已授权或授权被拒;
  结论同时写进**常驻状态行**(不再只是一闪而过的 Toast)。

**🎨 更新说明不再是一堆 Markdown 符号**

- **现象**:更新弹窗里塞的是 Release 说明原文,满屏 `#`、`**` 和表格竖线,手机上没法看。

## v0.2.4 修复清单(第二次真机日志)

第二次日志里带了页面 dump,暴露了两个问题:

- **离屏窗口拿不到焦点(根因级)**。之前覆盖窗口带了 `FLAG_NOT_FOCUSABLE`,页面 `document.hasFocus()` 恒为 false —— 浏览器不会给没有焦点的文档可用的 selection,Slate 这类**受控编辑器就永远拿不到插入点**:文字能被塞进 DOM,但编辑器内部状态一直是空的,于是回车无效、发送按钮保持 disabled、编辑器永不清空。现在去掉了这个 flag(保留 `FLAG_NOT_TOUCHABLE`,不抢触摸),并在装载后 `requestFocus()`;页面状态与输入结果都会带上 `focus=0/1`,一眼可确认。

## v0.2.3 修复清单(依据真机日志)

第一次真机运行暴露出两个具体故障点,已针对性修掉:

- **消息写进了输入框却没进编辑器内部状态**。日志表现为「消息已写入编辑器」但随后「回车未生效(notclear)」、编辑器永远不清空、发送按钮点不动。原因是 Slate/Draft 都是**受控编辑器**:直接 `document.execCommand('insertText')` 只改 DOM,编辑器内部仍认为自己是空的。现在改为**先派发粘贴事件(ClipboardEvent + DataTransfer)** —— 这是 Slate/Draft 都会处理的输入路径,模型才会更新;其次 `beforeinput/input`,最后才是 execCommand,并回读 innerHTML 是否真的变化,日志会写明用的是哪一种(方式=paste / beforeinput / execCommand / dom)。
- **记录发送按钮状态**:按钮保持 disabled 时日志直接写「⚠️ 发送按钮处于禁用状态」,一眼看出是"文本没进模型",不用再猜。
- **不再用全局 `.semi-spin` 判"发送中"**:抖音全站都用 semi 组件,任何一处转圈都会命中,之前把"其实没发出去"误报成了"还在发送"。
- **会话列表改为优先路径并支持滚动**:真机日志里列表点击稳定可用(搜索面板反而没出结果),所以现在先在列表里找、滚动逐轮查(滚不动就提前收手),找不到才走搜索;搜索填入后也会补一次回车。
- **搜索诊断**:填充会回报 `filled:len=N:ph=...`(文本有没有真的进搜索框),未命中回报 `empty:0/0/0/0/0`(每个候选选择器各命中多少节点),据此可区分"面板没出来"和"面板出来了但类名不对"。
- **编辑器残留保护**:上一轮没发出去时编辑器里会留下文本,再次输入会被拼接成一条怪消息;现在检测到残留会先重载聊天页再继续。

## v0.2.2 修复清单

**协议模式(此前完全不可用)**
- 运行标志 `PROTO_RUNNING` 用完不复位 → 一个进程只能成功运行一次;现在在 `finally` 里复位。
- `SparkService.ABORT`(停止运行按钮)在协议链路无人复位 → 点过一次停止后永久「已手动停止」;现在每轮开始时复位。
- 搜索框就绪检测接受任意输入框,真正填充时却只认一条硬编码选择器;结果项 / 编辑器 / 发送按钮同样只有单条选择器 → 全部改为多候选降级链。
- 页面内 25 秒定时器等待(SPA 跳转即丢失回调,必然超时)→ 改为 Java 侧短探针轮询。
- 输入只试 execCommand 一种方式 → 增加粘贴事件、beforeinput/InputEvent 兜底并回读校验。
- 回车不发送的版本没有兜底 → 自动改点发送按钮。
- 离屏 WebView 未开第三方 Cookie(登录页开了)→ 补上;`shutdown()` 的 `removeView` 抛异常会跳过 `destroy()`,WebView 与 Context 泄漏 → 分开兜底。

**无障碍模式**
- 「防发错人」校验两条分支都 `return true`,等于没做(README 却承诺会放弃)→ 顶部读到的是别的昵称时真的放弃该会话。
- 勾选 Root 解锁但解锁失败、用户自己解锁后,运行结束会把手机当面重新锁上 → 只有本轮确实是自己解锁的才回锁。
- Root 命令只读一行就 `waitFor`,输出超过管道缓冲会永久阻塞(该路径在 `finally` 里,卡住就收不了尾)→ 排空输出 + 15 秒超时;失败也不再被当成成功、不再清掉恢复标记。
- 锁屏恢复失败时清掉了唯一的崩溃恢复标记 → 保留待下次重试。
- 节点遍历 `getChildCount()` 在 try 之外,一个失效节点会终止整轮 → 纳入保护。
- 「解锁测试」留 10 分钟 `FULL_WAKE_LOCK` → 结束即释放。

**调度与配置**
- 无障碍/协议页只有一个时间输入框,但写的是 `sendTime`,调度只读 `times` → 用户改的时间被静默忽略且仍提示「已保存 ✓」;现在会同步进调度列表并明确提示。
- 覆盖安装/被强停后系统丢弃闹钟,只有开机广播会重建 → 增加 `MY_PACKAGE_REPLACED`,App 启动时也会在「一个有效计划都没有」时补排。
- `setExactAndAllowWhileIdle` 无 `canScheduleExactAlarms()` 判断,用户在 Android 12+ 关掉「闹钟和提醒」会直接崩溃 → 降级为非精确闹钟并记日志。
- `nextTime` 用 `+86400000` 加天数,抖动把时间推到过去时会整天后移(接近午夜的时间点约推迟 24 小时)→ 改用 `Calendar` 加天,先抖动再判断未来。
- 配置页先写盘再校验,「请填写好友名」的报错其实已经清空了好友列表并切换了模式 → 改为先校验后写盘。
- 「常驻保活」勾选只存不生效(取消后前台通知一直挂着)→ 保存时真正启停;改「随机抖动」不再需要等下一轮才生效。
- 切换页面会用配置覆盖未保存的输入 → 只在首次进入/保存后回填。
- 登录页 Cookie 轮询线程在 Activity 销毁后仍跑 30 分钟并能向已销毁界面弹 Toast → 增加销毁标志。
- 静默亮度缺少 `WRITE_SETTINGS` 声明,`canWrite()` 恒为 false、也不会出现在授权页 → 补声明。
