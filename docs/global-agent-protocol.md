## 本次优化做了什么

Codex 版 415 行协议 → 现行 49 行、6 个小节，6,054 字节、2,460 字符，占全局预算 9.2%（上限 65,536）。

**第一轮（-51.7%）**：按可执行性重写，删去目录树、签名、节号与论证性文字，合并「最小改动」等重复表述（原文重复 4 次），补回原第 10 节被漏掉的提交纪律。

**第二轮（再 -38%）**：按「永远要做 / 特定情况才触发」重组为两节，触发条件独立成行。

- **删掉纯元评论**（不改变任何行为，只为规则做辩护或复述优先级）：「判断需求是否合理是职责；给不出理由、证据和替代方案的质疑不算质疑」「冲突时不要用下层规则压上层：指出冲突并确认」「有更好方案就先提出，不要做完才说」。
- **删掉三处「检验标准」**：同一条规则在同一节里被说了两遍（如「每一行改动都能追溯到用户请求」）。
- **合并打补丁式重复**：`需求不合理、不清楚或成本过高时` 与主动语态版本并存；「不确定就问」曾出现三处。
- **结构**：「每个任务都做」8 条（无条件的），「触发式动作」7 条，每条以 `条件 → 动作` 开头。这是最大的可执行性提升——原先条件规则混在普通条目里，读起来无法判断何时该做。
- **修正过时内容**：原文写「动手前先读三份文档」会诱发空转（低价值、高成本），改为「项目确实有这些文档 **且** 任务涉及方向／非目标／已否决方案／历史踩坑」才读，其余情况明确跳过。
